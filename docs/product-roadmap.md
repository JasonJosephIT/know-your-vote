*Voter-facing web app of the Civic Awareness Project (CAP). Builds on the existing CAP pipeline (Profiler / Record / Fact-Checker / Orchestrator + Balance Audit) which produces the neutral, audited data this app reads. Source docs: `docs/prd.md`, `docs/product-vision.md`, `docs/design.md`, and the backend specs (`CAP_Schema_v1.md`, `CAP_Balance_Audit_Spec_v1.md`, etc.).*

## Build Philosophy

1. **Each phase ships something usable.** No phase leaves the app broken. After any phase, you can demo what you've built.
2. **Infrastructure before features.** Phase 0 sets up everything so feature work later is fast and clean.
3. **Magic moment first.** "Enter your ZIP → see every candidate side by side, fairly" works by the end of Phase 1. Everything else builds on top.
4. **Test as you go.** Each task includes a verification step. Don't save testing for the end.
5. **Progressive enhancement.** Start with the simplest working version, then layer on polish.
6. **Review before proceeding.** Push each completed phase as a PR and let a review agent (e.g. [CodeRabbit](https://coderabbit.ai)) review it before starting the next phase.
7. **Present, don't author.** The app only ever *reads* audited pipeline output — it never generates, edits, softens, or reorders a claim. Candidate order is a fixed neutral rule applied identically to all.
8. **Publish only what passes the audit.** A race is reachable by the public only when every candidate Profile has `balance_check_passed = true` **and** `race_publication.status = 'published'`. This is enforced in the query and in RLS, not just the UI.

## Agent Session Guide

### How to Use This Roadmap with Your Coding Agent

1. **Start a session:** Give your coding agent the phase prompt at the beginning of each phase.
2. **Read selectively:** Each phase lists its Reference sections — read only those parts of the PRD, vision, and design docs, not the whole files.
3. **Let it work:** The agent finds the first unchecked task, implements it, and marks it `- [x]`.
4. **One session = one phase (ideally):** Complete a full phase per session for continuity; resume from the last unchecked task if you stop.
5. **Push a PR for review:** When a phase is complete, push it as a PR and let a review agent (e.g. [CodeRabbit](https://coderabbit.ai)) review before starting the next phase.
6. **Need more context?** If a task references a section not in the phase's Reference sections, read just that section on demand (e.g. a task may point to `docs/prd.md § Payment Integration` — not used here — or a backend spec).

### Session Tips

- **Don't read everything.** The Reference sections tell the agent exactly what to load.
- **Don't skip tasks.** They're ordered so dependencies resolve by sequence.
- **Verify after each phase.** Run the app and confirm the phase goal before moving on.
- **Review before moving on.** Don't start the next phase until the PR is merged.
- **Update the status line.** After completing tasks, update `**Status:** X/56 tasks complete` and `**Current Phase:**` in this file's header.

### The one non-negotiable

Everything the app shows is audited pipeline output, presented with equal space and equal scrutiny. If a task ever tempts you to have the app author, edit, rank, or partisan-code candidate content — stop. That's the one line this product cannot cross. See `docs/product-vision.md § Product Principles` and `docs/design.md § Do's and Don'ts`.
