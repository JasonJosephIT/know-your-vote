# Live database audit — 2026-09-07

**Question asked:** is the live database in line with the MVP?

**Answer:** the schema is ready and internally consistent. The content is not —
every content row is still a demo fixture. And one finding is not about data at
all: **the ingest parser was missing a statewide federal race**, which no
amount of content work would have fixed.

Read-only audit against project `pqracitpmzpiqfnzlngw`. Every number below came
from a `SELECT`; nothing was written.

---

## 1. The finding that changes scope

### Florida has a 2026 U.S. Senate race, and the parser was skipping it

`intake.py` mapped the four state cabinet offices and `USR` (U.S. House) for
four districts. **`USS` was not in either map**, so every U.S. Senate filing
fell through to `skipped`.

It failed silently by design: skipping is the normal path for the ~90% of the
DoE file that is not a target race, so a dropped office looks exactly like a
dropped county commission seat. Nothing in the run report distinguished them.

The evidence was already in the repo and had been read past twice:

| Source | What it said |
|---|---|
| `data-ingest.md` §1, B1's whole-file table | **"`FED` (269 USR + 14 USS)"** — fourteen Senate filings on the live general file |
| Demo fixtures | `demo-fl-us-senate`, 4 candidates, `published` |
| `product-roadmap.md` TASK-066 (original) | "**9 races**, ~18–20 candidates" |
| `intake.py` | 8 races. No `USS`. |

**A correction I introduced, and the mechanism worth remembering.** On
2026-09-07 I rewrote TASK-066's line from *"9 races, ~18–20 candidates"* to
*"8 target races, 22 ballot candidates"*, citing B1 as a measurement replacing
an estimate. B1 measured the eight races the parser targets — it could not
measure a ninth it never looked at. I mistook the parser's scope for the
ballot's shape, and in doing so I overwrote the one number in the repo that
disagreed with the bug. **An estimate that contradicts a measurement is worth
reading twice before deleting**; the estimate was closer to the ballot than the
measurement was.

**Fixed 2026-09-07** (Stream P). `_STATEWIDE_RACES` became
`_NO_DISTRICT_RACES`, mapping office code to `(race_id, level)`:

```python
_NO_DISTRICT_RACES = {
    "GOV": ("FL-GOV-general", "state"),
    "ATG": ("FL-ATG-general", "state"),
    "CFO": ("FL-CFO-general", "state"),
    "AGR": ("FL-AGR-general", "state"),
    "USS": ("FL-SEN-general", "federal"),
}
```

`level` rides in the map rather than being inferred, because **statewide and
federal are different axes** and the old code conflated them — it hard-coded
`level = "state"` for everything with no district, which would have filed the
Senate race as a state office and misplaced it in the read model's
federal/state grouping. Tests: 115 (was 114), including one that pins the
Senate race as `federal` with a null district. Mutation-checked: removing
`USS`, and filing it under `state`, each fail the suite.

**Still open:** how many of the 14 `USS` filings are ballot-tier is unknown —
B1's per-race table only covers the eight races it targeted. The next DoE run
answers it. The demo fixture guesses four.

> **The general lesson for this map:** adding an office to it is the only thing
> that makes a race exist. Check it against the ballot, not against the last
> run's counts — the last run cannot report a race it never looked for.

## 3. Two problems in the news feed

### 3a. All four `election_news` rows are unattributed

Every one has `source_id IS NULL`. This is what stopped migration `0014`
(N1) being written as specified: a `CHECK` requiring a source on agent rows
cannot be added while existing rows violate it.

They are **not** unattributable, though — they are government pages:

| Row | Host | What it is |
|---|---|---|
| Broward early-voting windows | `browardvotes.gov` | Supervisor of Elections |
| Hillsborough early voting | `votehillsborough.gov` | Supervisor of Elections |
| Miami-Dade early voting | `miamidade.gov` | County |
| Florida HB 991 | `flsenate.gov` | Bill page |

The fix is mechanical rather than editorial: give each a `source` row with
`type='primary_doc'` and `lean_tag='N/A'`. **`N/A` is not a lean judgment** —
it is the schema's "lean does not apply", which is exactly true of a
Supervisor of Elections page. This is the one place backfilling source rows
does *not* require the kind of call that gates C7's outlet list.

Doing so is also a straight improvement for voters today: those four cards
currently render with no publisher and no label at all.

### 3b. Two of them describe an election that already happened

- *"Hillsborough to open 27 early-voting sites for **August 18 Primary**"*
- *"Miami-Dade sets early-voting schedule for **August 18 Primary**"*

The primary was 2026-08-18. These have been live on the feed for three weeks
past the event. That is voter-facing and it is a content decision, not a
schema one: delete them, or replace them with the general-election
equivalents from the same three counties.

**Founder call.** `0015` set the precedent for correcting primary-era copy in
a migration.
